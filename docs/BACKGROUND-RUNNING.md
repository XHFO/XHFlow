# 后台运行与系统恢复保护

部分小米电视固件会拒绝普通第三方应用登记前台服务，并在休眠或清理后台时强行停止应用。此时 `START_STICKY` 不一定生效，直接结束进程也不会调用 `onDestroy()`，仅在退出回调里安排闹钟无法覆盖这种情况。

0.5.1 增加独立的 `RevivalService`，通过用户授权的通知监听服务接受系统绑定，再直接托管原有配置与同步服务。系统清理后若重新绑定它，后台会读取已有设置恢复运行，不弹出主界面、不切换输入源。这个机制参考了 [aerial-tv 的恢复入口](https://github.com/pengchujin/aerial-tv/blob/adb78f88aa1b4200a44d6a768d1bc21b45884996/app/src/main/java/app/orchard/tv/guard/RevivalListener.kt)。XH光流不需要接管主页键，因此直接托管后台，不申请修改安全设置权限、不写回无障碍授权，也不增加系统账号或常驻唤醒锁。

## 开启与撤销

电视应用 → “管理后台守护” → “系统恢复保护”，在系统的“通知使用权”页面允许 **XH光流系统恢复保护**。部分电视隐藏这个系统页面，可以连接自己的电视后使用 ADB：

```sh
adb shell cmd notification allow_listener net.xhfo.tvwled/net.xhfo.tvwled.RevivalService
```

撤销使用系统设置，或：

```sh
adb shell cmd notification disallow_listener net.xhfo.tvwled/net.xhfo.tvwled.RevivalService
```

命令成功退出只代表系统接受了请求。请在应用或网页“启动与后台”中确认 **系统恢复保护已连接**；“已授权，尚未连接”不能视为保护已生效。需要进一步诊断时可检查 `adb shell dumpsys notification` 中本组件是否同时出现在 Allowed 和 Live 服务列表。该命令可能含其他应用通知信息，分享日志前请脱敏。

系统称其为通知使用权，但 XH光流没有实现通知内容回调，也不调用查询、取消或发送通知的监听接口；Android 12 及以上禁用全部四类通知过滤器。此前的辅助功能守护可以保留，两种保护独立显示真实状态。应用不会自动修改系统授权，不会阻止你撤销保护。

## 恢复规则

- 总开关开启：系统恢复后台后重新检查屏幕休眠、输入源与配置，再决定是否取色和输出。
- 总开关关闭：只恢复网页后台，灯光保持停止。
- 网页“开机运行”关闭：进程重建后不自动托管网页或同步；手动打开后可以保护本次会话。
- 授权撤销：不再通过这个入口托管后台，不自动重新授权。
- 绑定失败：每次系统连接或有效设置变化只做有限重试；关闭或撤销后，陈旧回调不会重新启动后台。

这是请求系统重新托管的恢复机制。固件是否保留授权、是否重新绑定、恢复延迟均由系统决定；不能保证所有机型、用户手动强行停止、关机断电或系统停用应用后的恢复。实际设备验证记录见 [验证记录](VALIDATION.md)。
