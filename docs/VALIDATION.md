# 验证记录

## 0.5.1：系统绑定恢复（本地真机测试）

目标设备：Redmi G Pro 32U 2026 / Android 14。2026-10-30 读取到此前数次进程退出均为 `USER REQUESTED / FORCE STOP`，原辅助功能守护不在授权列表，普通前台服务也未被固件登记。本次使用相同签名覆盖安装 versionCode 11，安装前后完整配置相等。

- 增加独立通知监听服务绑定，系统侧确认本组件同时出现在 Allowed 和 Live 列表，应用返回 `revivalAuthorized=true`、`revivalConnected=true`、`keepAliveMode=revival`。不依赖恢复已被移除的无障碍授权。
- 在离开主界面后，对本包执行 `am force-stop`，无需重新打开 Activity，观察到新 PID，最终包约 2.18 秒后重新出现新鲜取色及发送状态。系统恢复后也登记了前台服务。
- 关闭总开关后重复结束本包，最终包约 0.75 秒后网页后台恢复，`enabled=false`、`running=false`，未自行开启灯光。
- 在系统恢复的会话中关闭“开机运行”，网页保持可用；再次结束进程后，系统仍绑定恢复服务，但配置后台与取色不再自动运行。手动打开后网页正常可用，总开关仍关闭。
- 撤销恢复授权后，实际状态变为未授权、未连接，系统列表不再有本组件；观察期间没有自行恢复授权。测试后重新开启保护，恢复原总开关与开机设置，保存的完整配置相等。
- 全部 5 组网页测试及 16 套主机 Java 合约通过；新增 68 项恢复检查覆盖当前宿主、关闭后台、撤销授权、过期回调、关闭开机恢复保留现有会话及最多三次尝试。每次本地绑定最多等待 5 秒，不依赖无限重试。

上述时间是局域网轮询首次观察到的结果，包含请求与初始化耗时。这里模拟的是该固件上已观察到的强停路径，不代表所有 Android 设备都允许强行停止后的系统重绑；应用没有清除 stopped 标记或主动恢复已撤销授权。尚需长期运行与实际遥控待机/唤醒观察，不能把一次进程恢复测试等同长期保活验收。

目标设备：Redmi G Pro 32U 2026 / Android 14，1920×1080、密度 2.0。2026-10-29 覆盖安装非调试版 versionCode 10，原有完整配置保留。

- 左右标题在默认字号下同为 y=154–206，二维码与地址在标题和操作之间的空余区域视觉居中。三个底部控件实际边界均为 y=760–843，管理后台守护、总开关、返回画面同高同底线；主面板四边各留白 108 px。开关用强调色/灰色和滑块位置表达状态，没有轨道内文字；普通按键为圆角矩形。

- 网页在 390、900、1280 px 宽度检查，均无横向溢出；检查浅色与深色主题、折叠分组、本地自动保存后的刷新恢复、重置排布及一次撤销。
- 使用当前网页连接真实电视，将 Gamma 从 1 调为 1.01，停手后自动保存并安全应用，回读确认仅该字段变化，已保存/已应用指纹一致且总开关保持开启。随后通过网页恢复为 1，完整配置与测试前相等。

## 0.4.4：电影黑边取色修复

目标设备：Redmi G Pro 32U 2026 / Android 14。2026-10-29 已覆盖安装 versionCode 9，升级前后保存的完整配置相等，同步开关保持原状态。

- 旧算法在黑色和亮色探点之间取中点作为边界，低缩进时实际采样仍可能落在电影黑边内。已使用真实取色计划复现；修复后使用已观察到的内容侧边界，并保留两像素安全量，避黑不再依赖用户缩进。
- 每次黑边探测使用 18 点，分布于三列、两个相对边和三层深度；逐步细化边界，约每 750ms 交替检查横竖轴。均匀低亮灰黑边与单列字幕干扰均有测试覆盖。
- 四组网页测试与 11 套主机 Java 测试通过。新增黑边回归包含 1080p/4K、两档采样、0–20% 缩进、多种电影比例、字幕、画幅变厚/变薄、暗场保持和恢复满屏，直接检查实际像素坐标和灯珠映射输出。
- 设备连续观测的主取色与黑边探测均正常，无探测错误。发布 APK 为非调试构建，v2/v3 签名验证通过；使用相同签名覆盖升级。
- 安装后请使用者播放有上下黑边的电影并观察；使用者确认“没问题了”。这是本次电影场景的视觉验收反馈，没有将应用界面的取色观测当作电影画面验收。

暗场或宽字幕覆盖多数探点时仍可能延迟首次确认；全黑过场保留已确认区域。未在本次重新验收所有接口、HDR/DRM、整机休眠或后台强杀恢复。
